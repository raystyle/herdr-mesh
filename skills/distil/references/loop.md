# 四步环:执行、蒸馏、提案、闸门

> 一轮 = 蒸馏加提案加闸门;角色三分:执行者(项目 agent 正常干活)、蒸馏者(轨迹总结到模式页)、提案者(模式到一案)。一轮只出一案;单 agent 会话连任多角色时以回合为界换帽,流水记换帽痕,角色约束(防重提页只读等)按回合生效;闸门细则见 gate.md,层形态见 layers.md。

## 执行(产痕)

- 项目正常工作即产痕,轨迹总结按 layers.md 收口进 sources;不造玩具任务喂环,失败义务从项目已有可重复检查里抽(门禁红、评审打回、断链、用户纠正)
- 每轮开工先点名「当前标准盖不住的失败义务」:本轮提案要翻转的对象;载体 = 项目既有台账(ISSUE、REQ 等),台账判据即验收判据,前提是条目带可判验收判据,skill 不另立平行清单防第二真相;没有点名义务不开环(空转不记进度)

## 蒸馏(轨迹到模式)

- **有限样本**:失败为主(至多约 5 条)加成功为辅(至多约 3 条),分层取样;取样窗口缺省最近 1 至 3 日轨迹,建仓首轮收口豁免;窗口是蒸馏抽样不是保留期,已入库 sources 与知识页不因出窗失效,点名义务可回引窗外轨迹;样本先过资格过滤(layers.md),不合格不入样
- 纪律:禁改 sources 与 operations;不发明轨迹不支持的模式;写行动模式不抄报错;对照成功样本保留有效行为,失败样本给根因;环境私有发现(仅某端、某沙箱成立的)标注后端留 knowledge,不进双端共用的标准页
- 产出:新模式页或既有页修订(带 trace 引文),更新索引与流水;蒸馏完即提交 knowledge git(发生在提案与闸门之前,knowledge 不随后续回滚);蒸馏与提案回合可无头边界内跑(审批档位见 backends.md)

## 提案(模式到一案)

- **三选一,恰好一案**:
  - `create`:新标准 skill,整份 SKILL.md(官方 frontmatter、When to Apply、When NOT to Apply、步骤)加目的说明(链到支撑它的模式页)
  - `patch`:改既有标准 skill,锚定操作(append、replace、insert_after),锚点缺失即本轮提案失败,不硬套
  - `no_action`:证据不足或无可翻转义务,合法出口,不跑闸门、不动标准集
- 提案前必读防重提页,不重复已拒路线;至少读若干条失败轨迹再提;提案者不直接写 operations,候选由闸门应用
- 缺提案文件是事故,记流水并按失败处置,不得混记成正当 no_action

## 闸门(见 gate.md)

合取三条全过才提交标准集;任一不过回滚,提案全文进防重提页。

## 停机条件

- 无未覆盖的失败义务,或连续 no_action:停,报告存量与欠账
- 不设满分短路(项目没有「满分技能集」状态);不把 K 轮空转当进度
- 成本纪律:没有新失败义务不跑;蒸馏样本维持个位数;验证只跑合取谓词点名的义务加既有门禁,不重放全部历史
